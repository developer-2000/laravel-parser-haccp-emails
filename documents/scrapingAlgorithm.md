# Алгоритм сбора компаний

## 1. Старт: `searchQuery(int $id)`

- Формируется поисковая строка по id набора запросов.
    - Пример: `Fleischverarbeitung Impressum Kontakt Deutschland`
- Очищаются логи `search.log` и `crawl.log`.
- Диспатчится первая итерация **SearchJob** в очередь `search`.

---

## 2. SearchJob — обход поисковой выдачи

После того как `searchQuery` отправил задачу в очередь.

### 2.1. Запрос к DuckDuckGo

- На итерации 0 — обычный поиск (bare search).
- На следующих итерациях — POST с hidden-полями формы Next из предыдущей страницы.
- Запрос идёт через **Playwright** (headless-браузер).

### 2.2. Проверка ответа

После получения HTML.

- Сохраняется HTML итерации в `storage/logs/ddg-iteration-N.html`.
- Если ответ слишком короткий или содержит `captcha` → ретрай (до 3 попыток).

### 2.3. Извлечение ссылок из SERP

После того как HTML признан валидным.

- Парсятся ссылки с маркером `class="result__a"` из выдачи DuckDuckGo.
- Раскрываются редирект-обёртки `uddg=...`.

### 2.4. Нормализация URL

После извлечения сырых ссылок.

- Каждый URL приводится к виду `scheme://host` (без path/query/fragment).
- Это нужно, чтобы `site.de/impressum/`, `site.de/kontakt/`, `site.de/?q=foo` не попали в БД как 3 разные компании.

### 2.5. Дедупликация внутри батча

После нормализации.

- Удаляются повторы ссылок в текущей пачке.

### 2.6. Фильтр «мусорных» URL

После внутренней дедупликации.

Отсекаются категории, которые заведомо не являются производителями:
- Глобальные платформы и job-сайты (google, facebook, linkedin, indeed и т.п.).
- B2B-каталоги и агрегаторы (gelbeseiten, europages, kompass, branchenbuch).
- Магазины — по домену (`-shop.`, `.shop`, `-versand.`) и по пути (`/shop/`, `/warenkorb/`).
- Оборудование и техника (`-maschinen.`, `-anlagen.`, `/tumbler/`, `/kutter/`).
- Документы (PDF/DOC), регуляторы, ВУЗы, ассоциации/союзы (`-verband.`, `fleischerverband`).

### 2.7. Дедупликация с БД

После фильтра мусора.

- Одним запросом проверяется, какие URL уже есть в `companies`.
- Уже сохранённые отбрасываются.

### 2.8. Диспатч CrawlJob

После дедупликации.

- Для каждого нового URL диспатчится **CrawlJob** в очередь `crawl`.

### 2.9. Поиск формы Next и переход к следующей итерации

После диспатча CrawlJob.

- Из текущего HTML извлекается форма Next (DuckDuckGo пагинация).
- Если форма есть — диспатчится следующая итерация SearchJob с задержкой 2–5 сек.
- Если формы нет или достигнут предел итераций — обход останавливается.

---

## 3. CrawlJob — извлечение данных одной компании

После того как SearchJob поставил URL в очередь `crawl`.

### 3.1. Загрузка главной страницы

- Скачивается HTML главной с timeout.
- HTML приводится к UTF-8 (старые .de-сайты часто отдают ISO-8859-1 / Windows-1252).
- Если страница пустая или короче 1000 байт → выход без записи в БД.

### 3.2. Off-topic фильтр (Tier 2)

После загрузки HTML.

Проверяется `<title>` страницы. Отсекаются сайты с маркерами:
- Anlagenbau / Maschinenbau / Edelstahl / Verpackungstechnik.
- Verband / Verein / Innung / Bundesverband.
- Großhandel / Wholesale.
- Logistik / Spedition / Versicherung / Steuerberater / Statistik.
- Captcha-страницы блокировок (Human Verification, Security Check).

Если матчится — компания не пишется в БД.

### 3.3. Lead score (Tier 3)

После off-topic фильтра.

- Считаются баллы по словам в тексте страницы.
    - **+2** за каждое позитивное слово (produktion, herstellung, haccp, ifs, brc, lebensmittelsicherheit и т.п.).
    - **−3** за каждое негативное слово (restaurant, imbiss, online shop, lieferservice, warenkorb).
- Если итог `< 3` — компания не пишется в БД.

### 3.4. Извлечение данных с главной

После прохождения lead score.

- Email — через regex (3 прохода: сырой HTML, нормализация обфускаций, JSON-атрибуты `data-email`).
- Телефоны — только из текста рядом с маркерами `Telefon / Tel / Phone`.
- Название компании — из `<title>` (как fallback).

### 3.5. Стандартные пути контактов

После извлечения с главной.

- Скачивается `/impressum/` (юридическая информация, обязательна в ЕС).
- Скачивается `/kontakt/`.
- С каждой страницы извлекаются email и телефоны и добавляются в общий пул.

### 3.6. Поиск контактных ссылок в меню

После попыток стандартных путей.

Зачем нужен этот шаг:
- На некоторых CMS (typo3, joomla с pageid-навигацией) контакты лежат по нестандартному URL.
    - Пример: `https://www.fleischer-proesch.de/index.php?pageid=11`.
- Шаблонные `/impressum/` и `/kontakt/` на таких сайтах дают 404.

Что делается:
- В HTML главной находятся все `<a href="...">текст</a>`.
- Отбираются ссылки, у которых текст содержит **Kontakt / Contact / Impressum / Anfahrt / Standort**.
- Относительные href резолвятся в абсолютные URL.
- Берутся только ссылки на тот же домен (отсекаются facebook, google maps и т.п.).
- Лимит — 5 ссылок на компанию.
- Каждая найденная страница скачивается, email и телефоны добавляются в общий пул.

### 3.7. Чистка и дедупликация контактов

После сбора со всех страниц.

- Убираются дубликаты email и телефонов.
- Отбрасываются мусорные email:
    - Шаблонные имена (test, dummy, mustermann, noreply).
    - Псевдо-email из имён файлов (`logo@2x.png`, `flags@2x.webp`).
    - Tracking/телеметрия (Sentry, Wix, Google Analytics).
    - Длинные hex-username (DSN-идентификаторы).

### 3.8. Запись в БД

После чистки.

- Компания сохраняется/обновляется в `companies` по уникальному `url`.
    - `name` — из title.
    - `emails` — JSON-массив.
    - `phones` — JSON-массив.

---

## 4. Итог цикла

- Один `searchQuery(id)` запускает обход выдачи (несколько итераций SearchJob).
- Каждая итерация SearchJob отдаёт пачку URL в CrawlJob.
- Каждый CrawlJob независимо обрабатывает свою компанию и пишет результат в БД.
- Дубликаты страниц и компаний отсеиваются на трёх уровнях: внутри батча, через trash-фильтр, через сравнение с БД.
