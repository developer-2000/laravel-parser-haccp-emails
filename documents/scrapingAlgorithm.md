# Алгоритм сбора компаний

Описание работы парсера поисковой выдачи — простыми словами, шаг за шагом.

---

## С чего всё начинается

- Пользователь на главной странице:
  - Выбирает **тип бизнеса** (например — мясо).
  - Выбирает или вводит **поисковый запрос** для этого типа (один запрос на пару язык + тип).
  - Нажимает кнопку **«Отправить»**.

- Сервер проверяет:
  - Не завершён ли уже парсинг для этой пары (язык + тип бизнеса).
  - Если завершён — сразу возвращает «Этот парсинг завершён», ничего не запускает.
  - Если ещё не завершён — запускает обработчик в фоне.

---

## Откуда продолжать парсить

- Сервер хранит **указатель** на страницу поисковой выдачи, на которой нужно продолжить.

- Если указатель пустой — стартуем с самой первой страницы выдачи.

- Если указатель есть — продолжаем парсинг ровно с той страницы, на которой в прошлый раз остановились.
  - Это нужно, чтобы при остановке посередине (или просто между запусками) не пропустить уже пройденные страницы и не повторять их заново.

---

## Что происходит на одной странице выдачи

Один цикл — это обработка одной страницы поисковой выдачи DuckDuckGo. Состоит из нескольких этапов:

### Шаг 1. Получение страницы

- Парсер открывает страницу выдачи поисковика.

- Если ответ слишком короткий или содержит ловушку «captcha» — считает что нас заблокировали:
  - Делает паузу и пробует ещё раз.
  - Всего до **3 попыток**, с увеличивающейся задержкой (3 секунды → 8 секунд).
  - Если все три попытки провалились — записывает в лог «провал» и помечает задачу как упавшую (видно в Horizon).

### Шаг 2. Извлечение ссылок из выдачи

- Из страницы вытаскиваются **все ссылки на сайты**, которые DuckDuckGo показал в результатах поиска.

### Шаг 3. Очистка ссылок

- Каждая ссылка приводится к одной канонической форме — только адрес сайта без хвостов (`example.de`, без `/contact`, без параметров).

- Это нужно, чтобы один и тот же сайт не попадал в базу несколько раз через разные внутренние страницы.

### Шаг 4. Удаление дубликатов внутри страницы

- Если поисковик вернул один и тот же сайт несколько раз — оставляем только одну ссылку.

### Шаг 5. Отсев заведомого мусора

Из списка убираются сайты, которые точно не нужны — по простым правилам по адресу:

- Глобальные платформы: Google, Facebook, LinkedIn, YouTube, Wikipedia, Amazon и т.п.

- Каталоги и агрегаторы компаний (они только перечисляют производителей, сами ничего не производят):
  - gelbeseiten, europages, kompass, wer-liefert-was, northdata, и подобные.

- Магазины и розничные витрины (домены вида `*-shop.de`, `*-store.de`, и т.п.).

- Поставщики оборудования и техники (домены `*-maschinen.de`, `*-anlagen.de`, `*-edelstahl.de`, и т.п.).

- Документы (`.pdf`, `.docx`), сайты госорганов, университетов, ассоциаций и союзов.

### Шаг 6. Удаление уже сохранённых

- Оставшиеся сайты сверяются с тем, что **уже есть в базе компаний**.

- Если сайт уже сохранён — пропускаем (не нужно обходить его повторно).

- В лог попадает только список «дубликатов» — для трассировки.

### Шаг 7. Классификация по релевантности

Для каждой оставшейся ссылки парсер считает «оценку» — насколько сайт похож на нужный нам тип бизнеса:

- Смотрятся ключевые слова в самом адресе сайта.

- За каждое попадание начисляются плюсы (если слово профильное — например «fleisch», «metzger») или минусы (если слово негативное — например «shop», «industrie»).

- По сумме баллов сайт получает «уровень»:
  - **3** — идеальный (точно профильный производитель).
  - **2** — хороший (достаточно сигналов).
  - **1** — слабый (есть какой-то один сигнал).
  - **0** — мусор (никаких сигналов профиля).

- Сайты с уровнем **0** — отбрасываются прямо здесь, в очередь обхода не уходят.

- Сайты с уровнем **1 и выше** — идут дальше.

- В лог пишется сводка по каждому отбракованному адресу — какие именно слова сработали в плюс/минус. Это помогает понять, почему конкретный сайт не прошёл.

### Шаг 8. Постановка прошедших сайтов в очередь обхода

- Все «качественные» сайты с этой страницы выдачи скопом отправляются в очередь обхода (`crawl`).

- Это **отдельная фоновая очередь** — другие воркеры берут оттуда сайты по одному и обходят их (заходят на главную, ищут email/телефон на контактных страницах, сохраняют в базу).

- Используется массовая постановка (одним пакетом, а не по одному) — это быстрее: один пакетный запрос вместо N отдельных.

### Шаг 9. Переход к следующей странице выдачи

- Из текущей страницы выдачи парсер находит **«форму перехода на следующую страницу»**.

- Если форма есть:
  - Сохраняет указатель на следующую страницу в базе (чтобы при сбое можно было продолжить именно с неё).
  - Ставит в очередь себя же — но уже для следующей страницы.
  - Между страницами делается **пауза 2-5 секунд** — чтобы не нагружать поисковик и не получить блокировку.

- Если формы перехода нет — значит выдача закончилась:
  - В базе ставится отметка **«парсинг завершён»**.
  - Указатель очищается.
  - Следующий запуск этого же парсинга вернёт «уже завершён».

---

## Защита от повторов

- Указатель на текущую страницу выдачи **обновляется до отправки сайтов в очередь обхода**.

- Поэтому даже если парсер упадёт прямо сейчас — повторный запуск стартует ровно с той же страницы.

- Один и тот же сайт никогда не сохранится в базе дважды — на этапе записи срабатывает уникальность по адресу.

---

## Защита от ошибок

- Все сетевые ошибки и блокировки автоматически приводят к **повтору попытки**.

- До 3 попыток с увеличивающейся задержкой.

- Если все 3 попытки провалились — задача попадает в **failed_jobs** (видно в админке Horizon, можно вручную перезапустить).

- При этом указатель в базе остаётся актуальным — можно перезапустить с того же места.

---

## Когда всё это останавливается

Парсер заканчивает работу одним из двух способов:

- **Естественно** — поисковик отдал последнюю страницу выдачи (формы перехода больше нет).
  - Парсер ставит отметку «завершено», новый запуск этого же запроса больше ничего не делает.

- **Вручную** — если пользователь хочет перепарсить заново:
  - Достаточно очистить указатель и отметку завершения для нужной пары (язык + тип бизнеса).
  - Следующий запуск пойдёт с самой первой страницы выдачи.

---

## Что выполняется параллельно

- **Поиск** (этот алгоритм) и **обход сайтов** (отдельная очередь `crawl`) работают **одновременно**.

- Пока парсер уже листает следующую страницу выдачи — несколько воркеров обхода уже заходят на найденные ранее сайты и собирают контакты.

- Это даёт скорость: пока поисковик идёт по 30 страницам выдачи, найденные на первых страницах сайты уже обработаны и контакты сохранены в базу.
